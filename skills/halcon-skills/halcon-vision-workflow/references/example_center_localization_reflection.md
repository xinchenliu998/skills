## 自校验规则（5条，含新增规则5）

### 规则1：策略B与ROI几何中心的距离校验

**原理**: 如果策略B的结果与ROI几何中心过于接近，说明矩形拟合可能"退化"为ROI本身的外接矩形，而非目标模组的外接矩形。

```
ROI_Center = ((Row1+Row2)/2, (Col1+Col2)/2)
Dist_B_to_ROI = Distance(StrategyB_Center, ROI_Center)
ROI_Diag = sqrt((Row2-Row1)² + (Col2-Col1)²)

IF Dist_B_to_ROI < ROI_Diag * 0.02:    // B的结果距ROI中心 < 对角线的2%
    → ⚠️ 策略B可能退化为ROI几何中心，标记为不可信
    → 降低策略B的权重或完全弃用
```

### 规则2：策略B与策略C的一致性校验

**原理**: 如果策略B和策略C的结果差距过大，至少有一个不可靠。

```
Dist_BC = Distance(StrategyB_Center, StrategyC_Center)
Target_Size = sqrt(TargetArea)    // 最大连通域面积的平方根

IF Dist_BC > Target_Size * 0.1:    // 偏差超过目标尺寸的10%
    → ⚠️ B和C结果不一致，需要进一步判断谁更可靠
    → 触发循环思考
```

### 规则3：策略A的伪圆检测

**原理**: 如果圆拟合产生了半径差异极大的结果，说明有伪拟合。

```
Radius_Max = max(Radii[])
Radius_Min = min(Radii[])

IF Radius_Max / Radius_Min > 100:    // 最大半径与最小半径之比超过100
    → ⚠️ 存在严重伪拟合，策略A不可信

有效圆 = [r for r in Radii if r < ROI_Diag * 0.5 and r > 3]
IF len(有效圆) < 2:
    → 策略A不可用
```

### 规则4：策略C的面积占比校验

**原理**: 如果最大连通域面积占ROI面积的比例异常，说明分割可能有问题。

```
AreaRatio = TargetArea / ROI_Area

IF AreaRatio < 0.05:    // 目标面积 < ROI面积的5%
    → ⚠️ 前景提取可能不完整，重心不可靠
IF AreaRatio > 0.95:    // 目标面积 ≈ ROI面积
    → ⚠️ 可能把背景也当成了前景，重心退化为ROI中心
    → 必须检查Edge策略是否可作为补救
```

### 规则5：Edge与C的交叉一致性校验（★ 新增）

**原理**: 当Edge策略和策略C都有有效结果时，两者的一致性可以互相印证，提高置信度。

```
IF Edge.Valid AND C.Valid:
    Dist_Edge_C = Distance(Edge_Center, C_Center)
    
    IF Dist_Edge_C < 2.0 px:    // Edge和C高度一致
        → ✅ 互相印证，可提高置信度 (+0.15)
        → 即使规则4告警（C面积>95%），结果仍然可信
        → 说明"模组确实填满ROI"是真实场景，非误判
    
    IF Dist_Edge_C > Target_Size * 0.1:    // Edge和C偏差过大
        → ⚠️ 需要进一步分析哪个更可信
        → 检查Edge的覆盖度：
            IF Edge方法1（逐轮廓拟合）覆盖>50% → Edge更可信
            IF Edge方法2（整体包围）→ 可能Edge覆盖更全面
```

## 循环思考流程（更新版）

当任一自校验规则触发告警时，进入循环思考：

```
┌─────────────────────────────────────────────────┐
│              粗分析输出结果                        │
│   策略A: (RowA, ColA) or N/A                     │
│   策略B: (RowB, ColB) or N/A                     │
│   策略C: (RowC, ColC)                            │
│   策略Edge: (RowE, ColE) or N/A    ★ 新增        │
└───────────────┬─────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────┐
│           自校验规则检查                           │
│                                                   │
│   □ 规则1: B是否退化为ROI中心？                    │
│   □ 规则2: B和C是否一致？                         │
│   □ 规则3: A是否有伪圆？                          │
│   □ 规则4: C的面积占比是否正常？                   │
│   □ 规则5: Edge与C是否一致？ ★ 新增              │
└───────────────┬─────────────────────────────────┘
                │
        ┌───────┴───────┐
        │               │
   全部通过          有告警触发
        │               │
        ▼               ▼
┌──────────────┐ ┌──────────────────────────────────┐
│ 直接输出结果  │ │     循环思考（Loop Reasoning）      │
│ 按原策略优先级│ │                                    │
└──────────────┘ │ Step1: 标记不可信的策略              │
                 │   - 规则1/2告警 → 策略B标记不可信    │
                 │   - 规则3告警 → 策略A标记不可信      │
                 │   - 规则4告警 → 策略C标记不可信      │
                 │                                    │
                 │ Step2: 从剩余可信策略中选择          │
                 │   - 若仅策略C可信 → 直接采用C       │
                 │   - 若A和C都可信 → 加权平均         │
                 │   - 若B和C都可信但不一致             │
                 │     → 进入Step3                    │
                 │                                    │
                 │ Step3: 补救与交叉验证 ★ 新增扩展    │
                 │   传统补救:                         │
                 │   - 对策略B: 缩小ROI至目标区域      │
                 │     重新执行SmallestRectangle2      │
                 │   - 对策略C: 尝试不同阈值           │
                 │     检查重心是否稳定                 │
                 │                                    │
                 │   Edge补救（当传统策略全部不可信）:  │
                 │   - IF Edge.Valid:                  │
                 │     → 采用Edge结果                  │
                 │     → 检查Edge-C一致性(规则5)       │
                 │       IF 一致(<2px) → 提升置信度   │
                 │       IF 不一致 → 保持MEDIUM       │
                 │   - IF !Edge.Valid:                 │
                 │     → 输出ROI几何中心 + LOW         │
                 │                                    │
                 │ Step4: 若仍无法确定                  │
                 │   → 输出策略C或Edge结果+低置信度标记│
                 │   → 建议用户缩小ROI或提供更多信息   │
                 └──────────────────────────────────┘
```

## 置信度评分体系（更新版）

基于自校验结果，为最终输出附加置信度评分：

```
初始置信度 = 1.0

// 扣分项
IF 规则1告警（B退化为ROI中心）:
    IF 最终采用了B → 置信度 -= 0.4
    ELSE → 置信度 -= 0.1（说明系统正确避开了B）

IF 规则2告警（B和C不一致）:
    置信度 -= 0.2

IF 规则3告警（A有伪圆）:
    IF 最终采用了A → 置信度 -= 0.5
    ELSE → 置信度 -= 0.05

IF 规则4告警（C面积异常）:
    置信度 -= 0.3

// 加分项
IF 多策略结果一致（Dist_BC < Target_Size * 0.05）:
    置信度 += 0.1

IF 策略A同心圆检测成功且圆心距 < 5px:
    置信度 += 0.15

// ★ 新增加分项: Edge交叉验证
IF Edge.Valid:
    Dist_Edge_C = Distance(Edge_Center, C_Center)
    IF Dist_Edge_C < 2.0:      // Edge与C高度一致
        置信度 += 0.15          // 互相印证加分
    ELIF Dist_Edge_C < 5.0:    // 基本一致
        置信度 += 0.05

// 置信度等级
置信度 > 0.8  → HIGH（可直接使用）
0.5 < 置信度 ≤ 0.8 → MEDIUM（建议人工确认）
置信度 ≤ 0.5 → LOW（需要缩小ROI或切换方法）
```

### 置信度计算实例

**实验1（小ROI，策略全部一致）**:
- 初始: 1.0
- 所有规则通过，B和C一致(+0.1) → **1.0 → HIGH**

**实验2（大ROI，策略B退化）**:
- 初始: 1.0
- 规则1告警，未采用B: -0.1 → 0.9
- 规则2告警: -0.2 → 0.7
- 规则3告警，未采用A: -0.05 → **0.65 → MEDIUM**

**实验3（阈值失效，Edge补救）★ 新增**:
- 初始: 1.0
- 规则4告警(C面积99.7%): -0.3 → 0.7
- Edge与C一致(偏差0.93px < 2px): +0.15 → **0.85 → HIGH**
- 说明: 虽然规则4形式上告警，但Edge交叉验证证明了结果可靠

## 核心教训总结

1. **SmallestRectangle2的脆弱性**: 当ROI包含显著背景区域时，连通域的凸包可能包含背景噪声区域，导致最小外接矩形退化为ROI本身的矩形。**检测方法**: 矩形中心与ROI几何中心的距离 < ROI对角线的2%。

2. **区域重心的鲁棒性**: `BinaryThreshold('max_separability')` + `SelectShapeStd('max_area')` 组合对ROI大小变化具有天然免疫力，因为自适应阈值会正确分割前景，而选最大面积会排除小噪声区域。

3. **不能盲目平均**: 当两个策略结果偏差较大时，简单平均会产生一个"两边都不靠"的结果。应该先判断哪个策略可信，再决定是否平均。

4. **ROI的选取质量影响策略可靠性的优先级**:
   - 紧凑ROI（目标占比>80%）→ 所有策略都较可靠 → 按A>B>C
   - 宽松ROI（目标占比40-80%）→ 策略B可能受干扰 → 优先C
   - 过大ROI（目标占比<40%）→ 策略B大概率不可靠 → 仅信任C

5. **★ 阈值分割并非万能**: 当模组填满ROI（目标占比>95%）时，`BinaryThreshold`无法区分前景和背景（dark/light两种模式都失效），导致三策略全部失效。此时必须启用不依赖阈值的Edge策略作为补救。

6. **★ dark/light双模式必须都尝试**: 原来只尝试'dark'模式，对于亮色模组在暗背景上的场景会失败。每个策略都需要遍历两种模式，选择前景占比更合理的那个。

7. **★ 多策略交叉验证很关键**: 当Edge和C结果一致（<2px）时，即使规则4触发告警（面积>95%），也可以确认结果是可靠的。这说明告警≠错误，告警是提醒需要进一步验证，而不是直接否定结果。

8. **★ FitRectangle2ContourXld需要异常保护**: HALCON的矩形拟合对某些轮廓会抛出异常（#3266: No points found for at least one side），每个轮廓的拟合必须用try/catch包裹，不能让一个轮廓的失败影响其他轮廓的处理。

9. **★ Edge策略的覆盖度验证**: 单轮廓矩形拟合可能只覆盖ROI的40%，此时矩形中心偏向该边缘所在区域（如Col=1499偏向右侧），不代表模组整体中心。必须验证覆盖度>50%，否则转用整体SmallestRectangle2方法。
